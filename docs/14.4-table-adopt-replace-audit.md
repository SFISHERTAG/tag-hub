# Story 14.4 Audit — Table adopt-or-replace decisions for dead tables in 003

**Date:** 2026-08-23
**Baseline:** `448b741` (main)
**Auditor:** Apprentice session on ultracode
**Scope:** 15 dead Postgres tables in `functions/sql/003_migrate_firestore_to_postgres.sql`

---

## Executive Summary

Of 15 dead tables in 003 (17 total; only course_progress and dashboard_configs are queried):
- **3 ADOPT** — schema matches live Firestore data (auth_codes, webhook_dead_letter, bug_reports)
- **12 REPLACE** — schema incomplete, missing fields, or has governance issues (groups, tenants, appointment_outcomes, audit_log, ghl_agency_token, ghl_location_tokens, webhook_events_processed, clients, client_alerts, client_meta_creatives, users, csm)

The pattern repeats the locations/tenants trap: Firestore documents hold more fields than the Postgres schema captures. Four tables are dead code (never read or written). Two tables violate governance (missing from `docs/data-model.md`).

## REPLACE (12 tables)

### 1. groups
- **Firestore path:** `groups/{id}`
- **Decision:** REPLACE
- **Why:** Timestamp type mismatch (Firestore: number milliseconds, SQL: TIMESTAMPTZ). ID type mismatch (Firestore: string, SQL: UUID). Table is dead code — zero code references. Orphaned from migration.
- **Action:** Either update schema to match Firestore types or remove table entirely. Add groups collection to docs/data-model.md.

### 2. tenants
- **Firestore path:** `locations/{locationId}`
- **Decision:** REPLACE
- **Why:** Missing `owner_ghl_user_id` column used in production (Story 4.6, lib/dashboard/owner-calendar.ts, admin-tenants.model.ts, lib/dashboard/metrics.ts).
- **Action:** Add `owner_ghl_user_id TEXT` column.

### 3. appointment_outcomes
- **Firestore path:** `locations/{locationId}/appointmentOutcomes`
- **Decision:** REPLACE
- **Why:** Missing three actively-stored, actively-used fields: contactId, contactName, appointmentTitle. These are denormalized on write to enable follow-up queue rendering without per-row contact fetches (app/api/ghl/.../status/route.ts:149-158, lib/ghl/store.ts:313-314).
- **Action:** Add `contact_id TEXT`, `contact_name TEXT`, `appointment_title TEXT` (all nullable).

### 4. audit_log
- **Firestore path:** `locations/{locationId}/auditLog`
- **Decision:** REPLACE (or DELETE)
- **Why:** Dead code. Schema missing critical fields (auditEntryId, entryTimestamp, exitTimestamp) required for ImpersonationEntry type (Story 3.5). No code path reads from or writes to this table. All audit logging goes through Firestore (lib/audit/store.ts). Conflicts with docs/data-model.md which states "Replicated to Postgres? No".
- **Action:** If Postgres audit replication is needed, redesign schema to include auditEntryId, entryTimestamp, exitTimestamp, and a type discriminator to distinguish AuditEvent from ImpersonationEntry. Otherwise delete.

### 5. ghl_agency_token
- **Firestore path:** `ghl/agency`
- **Decision:** REPLACE
- **Why:** Missing `primaryCompanyId` field. This field records which agency's token serves locations with no recorded owner and is actively read/written in lib/ghl/store.ts. Split-brain risk: Postgres captures credentials but drops metadata.
- **Action:** Add `primary_company_id TEXT` (optional).

### 6. ghl_location_tokens
- **Firestore path:** `ghl/agency/locations/{locationId}`
- **Decision:** REPLACE
- **Why:** Missing `agencyCompanyId` field. Critical for routing location token re-mints to the correct agency (not primary fallback). Documented in docs/data-model.md and actively used in lib/ghl/tokens.ts.
- **Action:** Add `agency_company_id TEXT` (optional).

### 7. webhook_events_processed
- **Firestore path:** `webhookEventsProcessed/{source}:{eventId}`
- **Decision:** REPLACE
- **Why:** Naming convention mismatch (Firestore: camelCase, SQL: snake_case). Collection entirely missing from docs/data-model.md, violating CLAUDE.md governance: "Code may not declare a new Firestore collection or Postgres table without updating docs/data-model.md in the same commit."
- **Action:** Clarify naming convention (adopt camelCase across both for this table, or document the divergence). Add to docs/data-model.md.

### 8. clients
- **Firestore path:** `clients/{clientId}`
- **Decision:** REPLACE
- **Why:** Schema missing six fields from live Firestore documents: drive_folder_id, health_targets (JSONB), health_weights (JSONB), last_health_score, last_health_update, created_at. These are documented in docs/CSM_DASHBOARD_CONTEXT.md and present in setup-csm-test-data.ts. Split-brain: Firestore is authoritative but Postgres is incomplete reflection.
- **Action:** Add all six missing columns: `drive_folder_id TEXT`, `health_targets JSONB`, `health_weights JSONB`, `last_health_score NUMERIC`, `last_health_update TIMESTAMPTZ`, `created_at TIMESTAMPTZ`.

### 9. client_alerts
- **Firestore path:** `clients/{clientId}/alerts`
- **Decision:** REPLACE
- **Why:** ID type mismatch breaks referential integrity. Schema defines `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`, but Firestore documents have string IDs (auto-generated doc IDs like "aBcDeFgHiJk").
- **Action:** Change `id` to `id TEXT PRIMARY KEY` or add `firestore_id TEXT` column to maintain link between Firestore and Postgres records.

### 10. client_meta_creatives
- **Firestore path:** `clients/{clientId}/meta_creatives`
- **Decision:** REPLACE
- **Why:** Missing `id` field explicitly written to every meta_creatives document in Firestore (sync-creative-campaigns.ts:89). Schema captures only doc ID as creative_id, but misses the explicit id field also stored.
- **Action:** Document intent (is id redundant with doc ID, or should it be captured?) and either add `id TEXT` column or clarify in comment why it is intentionally excluded from replication.

### 11. users
- **Firestore path:** None (no Firestore source)
- **Decision:** REPLACE (or DELETE)
- **Why:** Anchor table for FK constraints only. No code queries this table. Firebase Auth is the authoritative user store; this table is meant to provide UID foreign keys for audit_log, bug_reports, and dashboard_configs. Dead code in Postgres — auth decisions happen in Firebase, not Postgres.
- **Action:** Determine if user anchor table is needed for Postgres FK constraints. If not, delete. If yes, clarify the strategy for populating it (should it be seeded, or filled on-demand when a user first writes to the system?).

### 12. csm
- **Firestore path:** `csm/{email}`
- **Decision:** REPLACE (or DELETE)
- **Why:** Firestore is the source of truth (lib/dashboard/csm-directory.ts:30). Postgres table is dead code — never queried. CSM org structure is stored in Firestore only.
- **Action:** Clarify whether Postgres csm table is needed for denormalization/performance. If not, delete.

## Pattern: Firestore documents hold more than their SQL schemas

This audit confirms the locations/tenants trap repeats across multiple tables:

1. **Firestore is the source of truth** but holds undocumented fields
2. **Postgres schema is incomplete** by design or oversight
3. **Dead code is created** when tables are built but never used (groups, audit_log)
4. **Governance violations** occur when tables are not documented in data-model.md

---

## Verification method

Each table was audited by:
1. Reading owner files (lib/ and app/api/ paths from Master's audit)
2. Checking the Firestore collection structure and read/write operations
3. Comparing against the 003 schema definition
4. Identifying missing fields and type mismatches
5. Confirming whether field gaps match live code or are dead schema

All findings cross-checked against code call sites, not documents.
