# Story 14.1 — Repository seam over every collection

**Epic:** 14 — Off Firestore
**Status:** Draft

## Story

As the architect migrating off Firestore, I need every app-side data access to go
through a typed repository, not directly to the Firestore SDK, so that 14.2
onward can swap the backing store without touching the 20 consuming files.

## Context

**Current state.** 20 files call `firestore()` — 18 in `lib/**`, 2 in
`app/api/**`. `lib/firestore.ts` is the only place the SDK is constructed. Full
inventory with line numbers in `docs/14.1-firestore-audit.md`, re-derived from
code at `635e14e`.

**The problem.** Without a seam, 14.3–14.10 are 20 scattered edits per
collection, and the dual-write window puts conditional store logic in every one
of them.

**The solution.** `lib/data/` exports one typed repository. Call sites change
once. The implementation swaps underneath them.

**Analogue.** Story 11.6 (courses store split) proved the sequence —
dual-write, backfill, verify by count, cut over, delete the old path — on a
collection whose worst failure is a missing training video.

## Scope

**In:** `lib/**` and `app/api/**`.

**Out:** `functions/**`. It is a separate npm workspace (`rootDir: ./src`) with
no path mapping to `lib/`, and it pins `@google-cloud/firestore` `^7.11.0`
against root's `^8.7.1`. A `lib/data/` module is not reachable from it.
Decided 2026-08-23: `functions/` folds into `app/api` in its own story, which
collapses `functions/src/firestore.ts` and the duplicated idempotency, GHL,
Slack, Drive and Postgres modules at the same time. Seaming it here would be
thrown away by that fold.

## Interface shape: path-scoped accessors

Ten of the 21 document paths are subcollections under a parent key
(`locations/{locationId}/auditLog`, `manual_pages/{pageId}/versions`,
`clients/{clientId}/alerts`, `ghl/agency/companies/{companyId}`, and others).
A flat `repo.auditLog.list()` cannot express them without smuggling the parent
key in as a query field, which hides the relationship that becomes a Postgres
foreign key in 14.2.

So the parent key is a parameter of the accessor, not of the query:

```typescript
repo.auditLog(locationId).list(filter)
repo.manualPageVersions(pageId).create(snapshot)
repo.clientAlerts(clientId).list()
repo.ghlCompanyTokens.get(companyId)
```

Top-level paths keep the plain form: `repo.groups.get(id)`, `repo.bugReports.list(filter)`.

The seam wraps the operations each call site actually performs. It does not
invent a uniform get/list/create/update/delete on every path — several paths are
write-only or read-only today, and speculative methods are surface area 14.10
would have to delete unused.

## Operations beyond get/set/query

These exist in code and the interface must carry them. Sites in the audit.

- **Transactions**, 2 sites. `lib/auth/otp.ts:140` (verify-and-consume a code)
  and `lib/audit/store.ts:148` (amend an audit entry). Both are read-modify-write
  under contention. The interface takes a transaction context through the
  methods so a Postgres implementation can bind it; the Firestore implementation
  passes the native `tx`.
- **Batch**, 1 site. `lib/knowledge-base/db.ts:91` writes the version snapshot
  and the page update together. A partial write loses revert history.
- **Collection group query**, 1 site. `lib/meta/retry.ts:155` scans
  `metaConversionLog` across every location for failed conversions. There is no
  per-parent form — the retry job does not know which locations have failures.
  The seam must expose an unqualified scan or the job cannot be written.
- **Multi-document read**, 1 site. `lib/ghl/store.ts:256` uses `getAll`.
  Without it the call degrades to N round trips.
- **Projection**, 1 site. `lib/ghl/tenants.ts:97` uses `select("locationId")`
  over every location. Dropping it turns a key scan into a full document read.

## Two leaks the enforcement must close

1. `lib/ghl/store.ts:33` does `export { firestore };`. Six modules import that
   file, so the handle escapes without anyone importing `lib/firestore`. An
   import-path lint rule alone does not catch this. Remove the re-export and add
   a symbol check.
2. `lib/webhooks/idempotency.ts` has no importers. It is a hand-synced mirror of
   the live `functions/` copy, and the two files each name the other
   authoritative. Delete it with the `functions/` fold rather than seaming dead
   code. Out of scope here; recorded so it is not seamed by mistake.

## Acceptance criteria

1. `lib/data/` exists with a typed repository: path-scoped accessors for the 10
   parent-scoped paths, plain accessors for the 11 top-level ones, and a
   Firestore-backed implementation. `lib/firestore.ts` is imported by that
   implementation and by nothing else.
2. All 20 call sites go through the repository and are free of `firestore()`.
3. The five non-CRUD operations above are expressed through the interface, not
   worked around: transaction context, batch, collection group scan, multi-get,
   projection.
4. `lib/ghl/store.ts` no longer re-exports `firestore`.
5. Unit tests cover the repository against a fake, and the two existing tests
   that reach the SDK (`lib/ghl/store.test.ts`, `lib/meta/retry.test.ts`) run
   against the seam instead.
6. An ESLint `no-restricted-imports` zone plus a pre-commit check blocks new
   `@/lib/firestore` imports and new `firestore` re-exports outside `lib/data/`.
7. `docs/repository.md` documents the interface and the contract 14.2+ builds on.
8. Build, test and lint pass. Story Status and Tasks updated in this commit.

## Dev notes

**This story creates the seam only.** The implementation stays 100% Firestore.
Dual-write is 14.3–14.9; 14.10 deletes `lib/firestore.ts` and drops the SDK.

**`docs/data-model.md` disagrees with the code** on collection names and on the
module count. Itemised at the end of the audit. Correcting it is its own change,
not folded in here, because it is the contract file under CLAUDE.md.

**The lint rule is load-bearing.** Without it new code bypasses the seam, and the
one existing bypass (the `lib/ghl/store.ts` re-export) shows it happens by
convenience rather than intent.
