# Story 4.5 — "As of" freshness indicator

**Epic:** 4 — Client owner dashboard
**Status:** Done

## Story

As a client owner, I want a visible timestamp showing when the dashboard data was last updated, so that I know if what I'm seeing is today's numbers or stale.

## Context

GHL data updates in real-time. Meta spend data refreshes on Meta's schedule (typically daily, can be 24h delayed). The dashboard should show "as of [date time]" so staleness is never ambiguous.

The "as of" time is the most recent timestamp across:
- Last appointment outcome marked (Story 2.3)
- Last contact added (Story 4.3)
- Last Meta API fetch (Story 4.2)

## Acceptance criteria

1. Query latest `markedAt` timestamp from appointment outcomes (Firestore).
2. Query latest `dateAdded` from GHL contacts.
3. Query latest Meta API response timestamp.
4. Display on dashboard: "Updated [date time ago] — Click to refresh"
5. Refresh button re-fetches all data and updates timestamp.

## Dev notes

Store Meta API fetch timestamp server-side when fetching (not in the response itself, since Meta doesn't provide it).

Refresh button triggers a server action that re-fetches all three sources and revalidates the page.

### Implementation notes (2026-08-18)

Epic 4 is greenfield — Stories 4.1–4.4 and 4.6 aren't built yet, so there is
no "client owner dashboard" page to attach a header to. Built this against

thing to shared dashboard chrome that exists today. When 4.2 adds its own
page, move `<FreshnessIndicator>` there if a dedicated header supersedes the
layout bar.

- [`lib/format/time-ago.ts`](../../lib/format/time-ago.ts) — relative time formatting, no existing utility to reuse.
- [`app/l/[locationId]/freshness-indicator.tsx`](../../app/l/[locationId]/freshness-indicator.tsx) — client component, refresh button.

**Dependency on 4.2/4.4:** `getAdSpend` and `getAdRoas` don't exist yet, so
nothing calls `recordMetaFetch` yet — the Meta source of `getLastUpdated`
will read as absent (not counted toward the max) until those stories land
and call it at fetch time. This was called out as acceptable in the story
brief ("shouldn't block on"); AC3's query path is fully implemented and
tested against the Firestore doc shape, it just has no writer yet.

GHL's contact list endpoint has no server-side sort by `dateAdded`, so
"latest contact added" scans the most recent page (limit 100) rather than
guaranteeing the true max across every contact — noted as a comment in
`lib/dashboard/freshness.ts`.
