# Story 14.B — Inline role string audit and periodic scanner

**Epic:** 14 — Off Firestore  
**Status:** Draft  
**Depends on:** Completion of 10.7 (legacy removal)

## Story

As a security maintainer, I need to find all hardcoded role strings in the tree and implement a periodic audit to catch drift, so that the role-isolation constraint is enforced tree-wide rather than only on new commits.

## Problem

The pre-commit hook `scripts/check-story-status.mjs` includes an inline-role check that scans for hardcoded role strings. It is diff-scoped: it only examines files staged for commit.

**Design intent:** Guard against NEW violations entering the tree.  
**Design gap:** Cannot find EXISTING violations. The hook has successfully prevented new inline roles from entering the tree, but three live violations already exist.

CLAUDE.md describes the role constraint as "enforced via pre-commit hook" but is silent about whether that covers the whole tree or only new commits. The gap is documented in `AGENT_COORDINATION.md §3`: a check that reports healthy while scanning a shrinking share of what it claims to cover.

## Root cause: Two independent holes in the check

The pre-commit check reports clean while the tree holds:
- **Production:** 26 lines containing 52 role-literal occurrences across 8 files
- **Test files:** 10 lines with 10 occurrences across 3 spec files (separate scope)
- **Legacy:** 135 lines across 29 files (pre-10.7 removal)

Two independent gaps explain this:

### Hole 1: Diff-scoping (documented, by design)

The pre-commit hook `scripts/check-story-status.mjs` only examines staged files:

```javascript
const diff = execSync('git diff --cached --name-only')
  .toString()
  .split('\n')
  .filter(Boolean);
```

**Intent:** Guard against NEW violations entering the tree.  
**Reality:** Cannot find EXISTING violations already in the tree.

This gap is correct-by-design for a commit gate. The issue is that CLAUDE.md describes the role constraint as "enforced via pre-commit hook" without clarifying whether that covers only new commits or the entire tree.

### Hole 2: File-level exemption (not in story, larger impact)

The hook applies a blanket pass to any file that imports or calls auth helpers. From `scripts/check-story-status.mjs:185`:

```javascript
if (!ROLE_HELPER_PATTERN.test(fileDiff) && !ROLE_HELPER_PATTERN.test(fullContent)) {
  // File uses no helpers; check for violations
} else {
  return null; // File is exempt; no violations reported
}
```

**Consequence:** A line like `const SUGGESTER_ROLES = ["tag_exec"]` violates the rule (bare `"tag_exec"` literal) but the file is exempt because it also contains `hasAnyRole()` somewhere, rendering the check ineffective. Three production files (`app/api/flow/` routes) and two dashboard files (`location-selection.ts`, `widget-definitions.ts`) both import `hasAnyRole` or `ROLES.*` but still contain hardcoded role strings in their role lists and widget registries.

**The fix:** Replace file-level exemption with line-level exemption. A line calling `ROLES.ADMIN` is allowed; a bare literal string is not, regardless of what else the file imports.

### Earlier pattern-based attempts (part of root cause)

Two attempts using pattern matching both returned clean on a tree containing violations:

1. **First attempt:** `git grep -nE 'role\s*(===?|!=)\s*["\047]'` — Used POSIX ERE, which has no `\s`, so the pattern silently matched nothing. Empty result looked like a clean tree.

2. **Second attempt:** `grep -rnP 'role\s*(===?|!=)\s*["\047]' | grep -vE '//|/\*|\*'` — Pattern `(===?|!=)` cannot match `!==`. Comment filter was too broad, removing any line containing an asterisk. Method only looked for comparisons, missing roles in object values and array literals. Empty result looked like a clean tree.

**The lesson:** A pattern that returns empty on a tree with violations is indistinguishable from a clean tree unless the pattern is validated against a known hit first. Before reporting "clean", test that the check can find a planted violation.

## Solution

### Part 1: Full-tree audit (this story)

Parse the canonical role list from `lib/auth/role-labels.ts`:

```javascript
const roles = [...parseKeyedRoles('lib/auth/role-labels.ts')].map(([_, v]) => v);
// Result: ["tag_exec", "tag_csd", "tag_csm", "admin", "client_owner", ...]
```

Scan for quoted role literals in any context (comparison, object value, array membership), excluding:
- The four definition files (lib/auth/role-labels.ts, web/src/app/core/models/role.model.ts, scripts/create-user.mjs, scripts/admin.mjs)
- Files that import sanctioned helpers (hasRole, hasAnyRole, isRole, effectiveRole)
- Comments and route paths (quoted strings in `path: '...'`)

### Part 2: Periodic scanner (this story or follow-up)

Implement `scripts/audit-inline-roles.mjs`:
- Runs the full-tree scan
- Reports all violations and categorizes by severity
- Can be invoked on-demand or as a CI gate to catch drift

**Where it runs:** Add to the pre-push hook (`scripts/pre-push.mjs` or equivalent), so developers are warned before pushing. Alternatively, run as a `npm run audit:roles` command and add to CI. A script nobody invokes is the same failure mode as a check that only scans diffs.

The fix for Hole 2 is a line-level exemption: a call to `ROLES.ADMIN` is allowed; a bare string `"admin"` is not, regardless of file context.

**On validation:** The audit method relies on parsing the real role list from `lib/auth/role-labels.ts` rather than hardcoding patterns. This is more maintainable and less error-prone than regex. Before finalizing the scanner, verify it catches all 41 known violations and correctly flags them for triage.
