# Story 4.3 — Funnel counts — leads, booked, showed, closed

**Epic:** 4 — Client owner dashboard
**Status:** Done

## Story

As a client owner, I want to see how many leads came in, how many booked, how many showed, and how many closed, so that I can see the funnel and spot where it's leaking.

## Context

These counts come from GHL contacts and appointments:
- **Leads:** total contacts added in last 30 days (via date_added)
- **Booked:** unique contacts with ≥1 appointment
- **Showed:** unique contacts with appointment marked "showed"
- **Closed:** unique contacts with closed-won opportunity (status = "won")

Story 2.3 and 2.6 ensure appointments and outcomes are marked; this story surfaces the aggregates.

## Acceptance criteria

1. Query: all contacts added in last 30 days.
2. For each, count appointments and their outcomes (showed/no-show/DQ).
3. For each, check if they have a won opportunity.
4. Display as a funnel: Leads → Booked → Showed → Closed, with counts and drop-off % at each stage.
5. Refresh on page load (no caching).

## Implementation

`lib/dashboard/funnel.ts` — `getFunnelCounts(locationId, days)` fetches
contacts (`searchContacts`), filters to `dateAdded` within the window, then
pulls appointments over the same window (`getAppointments`) and matches by
`contactId` for Booked/Showed, and open-pipeline won opportunities
(`getPipelines` + `getOpportunities(status: "won")`) matched by
`contact.id` for Closed. No `revalidate` is set on any underlying `ghl()`
call, so every page load refetches (AC5).

`getDashboardFunnelCounts(days)` wraps it with the same single-tenant
`devLocationId()` resolution `getPipelineBoardSummary` and `getTodayCalls`
already use, since the dashboard doesn't yet route a session to a specific
client's GHL location.

`app/dashboard/widgets/funnel-chart.tsx` (`FunnelChart`) renders the
Leads → Booked → Showed → Closed table with per-stage "of previous" and "of
leads" percentages, heat-shaded on the "of previous" conversion rate so the
weakest stage is visually obvious (AC4).

Wired into `app/dashboard/page.tsx` → `page-client.tsx` → `widget-grid.tsx`:
the `leads_funnel` widget now renders `FunnelChart` with live data whenever
the page fetched it, falling back to the existing mock-metrics `FunnelTable`
only if it didn't (defensive — in practice `page.tsx` always fetches it
when a `leads_funnel` widget is on the page).

Note: contact fetch is capped at the `searchContacts` default page (100),
matching the single-page pragmatism `getPipelineBoardSummary` already
uses for pipelines (`pipelines[0]`) — pagination isn't wired up yet, so a
location adding >100 leads in the window would undercount. Flagged for
follow-up, not blocking for the current single-tenant scope.

## Dev notes

Drop-off % at each stage helps identify the bottleneck:
- High Leads→Booked drop: targeting or funnel issue
- High Booked→Showed drop: reminder sequence or lead quality
- High Showed→Closed drop: closer performance or offer fit
