# Story 13.2 — Fulfillment stage model parity

**Epic:** 13 — Lifecycle handoff and churn prevention
**Status:** Draft
**Depends on:** none

## Story

As a client in onboarding, I want every stage of the real pipeline to be a stage
the app understands, so that my checklist does not silently disappear.

## Context

Live defect, found by the 2026-08-21 audit of location `rb6hPt8Ue77L4abghRMc`.

The real Fulfillment pipeline has 11 stages:

```
New Client · Onboarding Call · PR 1 - Slack, GHL, & Skool · AP 1 - Intake Complete
PR 2 - VSL Scripts · PR 3 - VSL Creatives · PR 4 - Creative Edits
AP 2 - Ads Launched · AP 3 - 1st Deal Closed · AP 4 - Closer Recruit · AP 5 - Ascension
```

`FULFILLMENT_STAGE_ORDER` in `lib/onboarding/stage-tasks.ts` knows seven: PR1,
PR2, AP1 through AP5. **PR3 and PR4 do not exist in the code.**
`parseFulfillmentStage("PR 3 - VSL Creatives")` produces `"PR3"`,
`isFulfillmentStage` rejects it, and the caller gets `null`, which renders as no
checklist at all.

Nobody is sitting at PR 3 or PR 4 today, which is the only reason this has not
been reported. It becomes a live bug the moment someone is moved there, and 13.5
cannot assign an SLA to a stage the code does not model.

Note also that the real order interleaves: AP 1 sits between PR 1 and PR 2. Any
code assuming PR stages all precede AP stages is wrong about this pipeline.

## Acceptance criteria

1. `FULFILLMENT_STAGE_ORDER` matches the live pipeline exactly, including
   `New Client` and `Onboarding Call`, in the pipeline's real order.
2. `parseFulfillmentStage` resolves every one of the 11 live stage names.
3. Stages with no checklist yet return an empty task list, distinguishable from
   an unrecognized stage. "No tasks defined" and "I do not know this stage" must
   not render identically.
4. A test asserts the full live stage list, so the next pipeline edit fails a
   test instead of failing a client.
5. Ordering is derived from GHL's `position`, not from the PR/AP code, since the
   two disagree.

## Tasks

- [ ] Extend `FULFILLMENT_STAGE_ORDER` to the 11 live stages
- [ ] Handle `New Client` and `Onboarding Call`, which carry no PR/AP code
- [ ] Separate "no tasks" from "unrecognized stage" at the call sites
- [ ] Define task lists for PR 3 and PR 4, or record that they are intentionally empty
- [ ] Test pinning the live stage list and ordering
- [ ] Gate: `npm run test`, `npm run lint`, `tsc --noEmit`
