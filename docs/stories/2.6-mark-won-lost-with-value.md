# Story 2.6 — Mark won / lost with value

**Epic:** 2 — Closer workspace
**Status:** Done

## Story

As a closer or TAG sales rep, I want to mark a deal won or lost and confirm
its value, so that pipeline totals and downstream ROAS reporting reflect
what actually closed.

## Context

`Opportunity.status` and `monetaryValue` are already read and displayed
(Story 2.1), but nothing writes them; closing a deal still means leaving the
Hub for GHL. This is upstream of more than the board: `docs/prd.md`'s ROAS
math (Epic 4) and conversion dispatch (Epic 6) both depend on
`monetaryValue` and `status` being accurate and current on the opportunity,
since that is the only source either epic will read from.

## Acceptance criteria

1. A deal can be marked won or lost from the board or a detail view.
2. Marking a deal won requires an explicit monetary value; zero is a valid
   value but must be entered, not silently defaulted.
3. The write updates both `status` and `monetaryValue` on the opportunity
   via a new function in `lib/ghl/opportunities.ts`.
4. A won or lost deal leaves the default "open" board filter immediately,
   consistent with the existing `STATUS_FILTERS` behavior in `app/page.tsx`.
5. Marking won with no value, or closing a deal that is already won or
   lost, is rejected with a clear inline error rather than a silent no-op.
6. No separate Firestore record is created for the close itself; GHL
   remains the system of record for opportunities per `docs/architecture.md`'s
   data boundary. Outcome timing (Story 2.3) is the only opportunity-adjacent
   thing Firestore holds, and this is not that.
