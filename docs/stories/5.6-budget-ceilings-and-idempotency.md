# Story 5.6 — Budget ceilings and idempotency

**Epic:** 5 — Onboarding and campaign launch
**Status:** Ready

## Story

As TAG, I want to ensure campaigns never exceed budget ceilings and can safely be re-created if something fails, so that we don't accidentally overspend or leave a client half-configured.

## Context

**Budget ceilings:** each offer has a max monthly spend (e.g., "tax prep max $2000/mo"). Form (5.2) enforces this; this story enforces it server-side.

**Idempotency:** if campaign creation (5.4) fails mid-way (e.g., campaign created, ad set created, ads fail), a retry should not duplicate. Store the created campaign ID so a second call skips creation and returns the same ID.

## Acceptance criteria

1. Each offer has a configured max budget (hardcoded for MVP).
2. On campaign creation (5.4): validate requested budget ≤ max. Reject if over.
3. Store campaign ID in Firestore at creation time (Story 3.5 audit log, or separate).
4. On retry of creation: check Firestore for existing campaign ID, return it instead of re-creating.
5. Test: creating twice with same inputs returns same campaign ID both times.

## Dev notes

Idempotency key: hash of (locationId, templateId, form inputs) so accidental re-submits (double-click, retry) don't duplicate.

State store: tracks created adset IDs, ad IDs, etc. for cleanup if activation fails.
