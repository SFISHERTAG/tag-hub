# Story 11.1 — Runnable Angular gate: Node floor pinned and enforced

**Epic:** 11 — Migration readiness
**Status:** Done

## Story

As anyone committing to `web/`, I want the Angular gate to actually run, so that
"tests pass" means the tests ran.

## Context

Written retrospectively so Epic 11's table has a story behind every row.

The Angular CLI requires Node `v22.22.3`, `v24.15.0` or `v26.0.0`. The dev
machine ran `v24.14.0`, one patch short. So `ng build`, `ng test` and `ng lint`
all refused to start.

Items 1 through 3 of the definition of done were therefore unrunnable, and
`web/**` changes had been landing with their own gate never executing. Nothing
reported this, because a gate that cannot start does not report failure — it
reports nothing, which reads identically to not having been reached.

Fixing it immediately surfaced four lint errors in code that had been committed
as verified. That single data point is the argument for the whole epic.

## Acceptance criteria

1. The supported Node range is declared, not assumed. ✓
2. npm rejects a wrong runtime rather than letting the CLI discover it. ✓
3. The version is pinned somewhere a version manager reads. ✓
4. The Angular gate runs in the pre-commit hook when `web/` is touched. ✓
5. A missing `web/node_modules` fails with a message saying what to run, rather
   than a CLI error. ✓

## Tasks

- [x] Run the Angular gate from the tracked pre-commit hook, only when `web/`

## Dev notes, the general form of this bug

A check that cannot start is worse than a missing check, because a missing check
is visibly missing. This one produced green commits for as long as it was
broken, and the people making them had no reason to doubt the result.

Worth applying the same question to the other gates: `functions/` tests are
excluded from the root vitest run and `check:functions` is build plus lint only,
so those tests run in no gate at all. Same failure shape, still open, recorded
in `docs/RESWEEP_DEPLOY_RUNBOOK.md`.
