# Story 2.3 — Outcome timing capture

**Epic:** 2 — Closer workspace
**Status:** Done

## Story

As a closer, I want to mark an appointment Confirmed, Showed, No-show, DQ, or
Cancelled in one click, so that outcomes get recorded without leaving the day
view, and so that show rate becomes measurable.

## Acceptance criteria

1. Each appointment on `/today` carries one-click controls for all five
   outcomes. ✓
2. Choosing an outcome updates optimistically and rolls back with a visible
   error if the GHL write fails. ✓
3. The outcome writes to GHL's `appointmentStatus` field, which stays the
   system of record. ✓
4. Alongside the GHL write, the Hub records when the outcome was marked
   relative to the appointment's start and end time (pre-call, on-call,
   post-call) in Firestore, since GHL has no field for this and the
   distinction is what separates a targeting failure (pre-call DQ) from a
   real disqualification (on-call DQ). ✓
5. A failed Firestore write does not block or roll back the GHL status
   write; the GHL write is the closer's actual work, timing is analytics
   context. ✓
6. GHL has no native "DQ" status; it maps onto GHL's `invalid` value. ✓

## Implementation

`app/today/status-controls.tsx` (client component, `useTransition` for the
optimistic update) calling the `markAppointment` server action in
`app/today/actions.ts`, which calls `setAppointmentStatus` in
`lib/ghl/appointments.ts` and then `classifyTiming` / `saveAppointmentOutcome`
in `lib/ghl/store.ts`. Firestore document:
`locations/{locationId}/appointmentOutcomes/{appointmentId}`.
