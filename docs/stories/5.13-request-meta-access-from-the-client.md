# Story 5.13 — Request Meta access from the client

**Epic:** 5 — Onboarding and campaign launch
**Status:** Not implemented — code exists, nothing runs it

## Story

As TAG, after a client submits intake, I need to either request system-user
access to their existing Meta ad account or send them a setup guide if they have
none, so the Meta side of onboarding starts without someone remembering to email
them.

## What this is NOT

**It does not wire up Meta.** The existing code contains **zero** references to
the Graph API, the Marketing API, or `META_SYSTEM_USER_TOKEN`. It sends email
and posts to Slack.

This matters because the name "Phase 3 — Meta Ad Account Setup" reads as though
Meta integration happens here. It does not. Its own header says "Awaiting human
verification of Meta access grant". The actual system-user connection is manual
work done by a person afterwards.

## What the existing code does

`functions/src/webhooks/phase3-meta-setup.ts`, undeployed:

1. Check whether the intake form supplied a Meta ad account ID
2. If yes, email a system-user access request
3. If no, email a setup guide
4. Write the Meta details onto the location record (`saveTenantResources`)
5. Notify TAG in Slack, and the client

## Acceptance criteria

1. [ ] A client who supplied an ad account ID receives the access request; one who did not receives the setup guide
2. [ ] The Meta details reach the tenant record and are readable by the dashboard
3. [ ] The endpoint enforces its secret. **`checkWebhookSecret` must not be used**
4. [ ] Re-delivery does not send a duplicate email
5. [ ] The endpoint is verified reachable and enforcing as part of done, not later
6. [ ] **The story states plainly, in the product docs, that a human still grants access afterwards.** The current naming implies otherwise and that misled the person who owns this system

## Risks

Same as 5.12: `deploy:phase3` carries `--allow-unauthenticated` and the handler
uses the warn-only `checkWebhookSecret`. Do not redeploy as-is.

## Dev notes

**Sequencing against Epic 17.** Epic 17 is end-to-end campaign orchestration and
assumes "Meta account ready" as its starting point. This story is part of how a
client reaches that state, and it is not running. Epic 17's premise is currently
untrue for any new client.

**Ask what actually happens today.** If Meta accounts are being connected for
clients, someone is doing steps 1 to 5 by hand. That person's process is the
real specification, and it should be written down before this is rebuilt from
the undeployed code.
