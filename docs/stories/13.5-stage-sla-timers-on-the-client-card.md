# Story 13.5 — Stage SLA timers on the client card

**Epic:** 13 — Lifecycle handoff and churn prevention
**Status:** Draft
**Depends on:** 13.2, 13.3

## Story

As a CSM, I want to see how long a client has been stuck at their current stage,
so that I intervene before they churn rather than after.

## Context

This is the churn-prevention half of the epic, and the reason the pipeline is
worth populating at all.

GHL has no native SLA on a stage. It has to be computed from
`lastStageChangeAt`, which `updateOpportunityStage` already returns, against a
per-stage threshold this story defines.

The 2026-08-21 audit is the argument for it: 35 of 37 opportunities sit at
`New Client`, several for a long time, and nothing anywhere says so. A timer
nobody is shown is just a stored timestamp, which is why the acceptance criteria
below are about where it appears rather than how it is calculated.

Depends on 13.2 because a per-stage threshold cannot be assigned to a stage the
code does not model, and PR 3 and PR 4 are currently unmodelled.

## Acceptance criteria

1. Each Fulfillment stage carries an SLA threshold, defined in one place.
2. Time in current stage is computed from `lastStageChangeAt`. Where that is
   absent on an existing record, the display says unknown rather than showing a
   misleading zero or the record's creation date.
3. The timer appears on the client card in the portfolio.
4. The timer appears in the client modal.
5. Breach is visually distinct from approaching, and both from healthy, without
   relying on colour alone.
6. Sorting or filtering the portfolio by time in stage is possible, so the worst
   case is reachable without reading every card.
7. Styling flows from M3 tokens. No raw hex in any component `.scss`, per the
   theme contract.

## Open questions

- Thresholds per stage: who sets them, and are they the same for every client?
- Does a breach notify anyone, or is it only visible to whoever opens the
  portfolio? A visible-only timer prevents churn only for clients someone was
  already looking at.
