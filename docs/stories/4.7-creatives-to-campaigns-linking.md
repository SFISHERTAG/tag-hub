# Story 4.7 — Creatives to campaigns linking

**Epic:** 4 — Client owner dashboard
**Status:** Backlog — shipped without a story, real state unverified

## Why this is a backlog item for shipped code

This shipped in August 2026 as "CSM Dashboard Phase 3" and was documented in six
`PHASE_*.md` files rather than a story. **No epic owns it.** Five of those
documents were point-in-time status reports and were retired on 2026-08-23; the
API reference survived as `docs/creatives-campaign-linking-reference.md`.

The name is also why it hid: "Phase 3" simultaneously named an unrelated
client-provisioning webhook, now story 5.13. Two live workstreams, one label,
zero stories. This is the case that produced `AGENT_COORDINATION.md` §11.

## What is shipped

- `lib/meta/creatives.ts`
- `app/api/clients/[clientId]/creatives/route.ts` — creatives from Google Drive,
  annotated with the campaigns using each one
- `clients/{clientId}/meta_creatives` in Firestore holds the `campaigns_using`
  links

Creatives themselves come from Drive via `fetchCreatives`; the subcollection
supplies campaign badges only. Migrated onto the repository seam in story 14.1.

## Known issues, found while writing this

1. **The seed scripts populate a path nothing reads.**
   `scripts/setup-test-data.mjs:86` and `scripts/setup-csm-test-data.ts:65`
   write `clients/{id}/creatives`, while the app reads
   `clients/{id}/meta_creatives`. Anyone seeding a test environment sees an
   empty read path and concludes the feature is broken — or worse, that it works
   because it renders zero rows without erroring.
2. **The route carried an `import/no-restricted-paths` exemption** whose comment
   described it as a migration marker into `lib/dashboard/metrics.ts`. Story
   14.1 removed the directive because the seam made it unnecessary, and kept the
   underlying concern: this still queries directly rather than through a scoped
   metric fetch.

## Acceptance criteria

1. [ ] Record what the feature is meant to do, in product terms, from someone
   who wanted it rather than from the code
2. [ ] Fix or delete the two seed scripts writing `clients/{id}/creatives`
3. [ ] Decide whether the campaign-link read moves into the metric registry, per
   the concern the removed lint exemption recorded
4. [ ] Confirm it still works against a real client with real Drive creatives —
   `campaignLinksIncluded` exists precisely because the link lookup can fail
   independently, and nobody has checked which state production is in
