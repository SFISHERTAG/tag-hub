# Story 10.4 — Shared M3 primitives, portfolio and bug reports

**Epic:** 10 — Angular migration
**Status:** Draft

## Story

As any signed-in user, I want the first real screens in Angular, built on shared
Material 3 primitives that every later feature reuses rather than reinvents.

## Context

Split from the old 10.4 on 2026-08-21. That number carried two different
stories: `docs/epics.md` used it for this one, while the story file of that
number was a production-hardening and release story. The release story moved to
10.8, where a release belongs. This is the feature story, and it is the one
Story 11.4 calibrates its estimates against.

It is deliberately first among the feature stories, and deliberately small.
`features/` currently contains one directory, `auth`. Everything a feature needs
that is not a feature — a page shell with a title, an empty state, a loading
state, an error state, a data table, a confirm dialog — does not exist yet. The
first feature story either builds those or inlines them, and inlining them means
10.5, 10.6 and 10.7 each invent their own.

Portfolio and bug reports are the right first features because they are the two
simplest real screens in the app. Portfolio is a list of tenants with an action;
bug reports is a form and a list. Between them they exercise the whole path
end to end — endpoint, typed service, guard, list, form, empty and error states —
without the parent-route resolver that makes 10.5 large.

That is also what makes this the calibration story. It is the smallest complete
instance of the work that 10.5, 10.6 and 10.7 repeat at scale, so its numbers
are the unit the rest are estimated from.

## Acceptance criteria

1. `shared/ui/` holds the primitives later features consume: page shell, empty
   state, error state, loading state, data table, confirm dialog. Each is
   standalone, `OnPush`, and themed only through M3 system tokens.
2. No component `.scss` declares a raw hex colour, and nothing uses
   `!important` or a deep selector.
3. `features/portfolio/` lists the caller's tenants and can enter one, reading
   an `app/api/**` endpoint rather than importing `lib/`.
4. `features/bug-reports/` submits and lists, through its own endpoint.
5. Both features are lazy-loaded and appear in the nav only for roles whose
   route guard admits them.
6. The endpoints re-check authorisation server-side. A route guard decides what
   renders; the API decides what is reachable.
7. The Next pages these replace are deleted in the same commit and the routes
   point at Angular.
8. `ng build --configuration production && ng lint && ng test --watch=false`
   pass, and the initial bundle stays under budget.
9. The four calibration numbers from Story 11.4 are recorded in this doc.

## Dev notes, why the primitives belong here rather than in 10.1

10.1 was contract hardening and was deliberately feature-free: lint zones,
strict mode, guards, the boundary the build enforces. Primitives are not
contracts. Designing an empty state before any screen needs one produces a
component shaped by imagination rather than use.

Building them here, against two real screens, means they are shaped by two real
consumers. Building them any later means 10.5 has already inlined its own.

## Dev notes, what "smallest complete instance" has to include

If this story skips the endpoint layer by having portfolio read something that
already exists, it stops being a calibration instance and its numbers stop
transferring. The point is that it does every step 10.5 does, at the smallest
scale where each step is still real.
