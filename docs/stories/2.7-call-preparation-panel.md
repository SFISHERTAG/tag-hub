# Story 2.7 — Call preparation panel

**Epic:** 2 — Closer workspace
**Status:** Ready

## Story

As a closer, I want relevant contact history and attribution surfaced
before a call starts, so that I walk in knowing who I'm talking to without
tabbing to Contacts.

## Context

`/today` (Story 2.2) shows only time, title, and calendar per appointment.
Contact-level attribution and notes already exist on
`/contacts/[contactId]` (Story 2.4); this story brings that context onto
the day view itself rather than requiring a closer to leave it mid-shift.
Every appointment already carries a `contactId` (see the `Appointment` type
in `lib/ghl/appointments.ts`), so the join is straightforward once the
shape of the panel is decided.

## Decisions

- Presentation: a modal, opened per appointment row. No inline expansion
  and no default data fetch per row on `/today` — the fetch happens only
  when a closer opens the modal, so the dense day view stays fast per
  `docs/architecture.md`.
- Notes: the most recent note shown in full, with the rest of the contact's
  note history folded underneath (collapsed, expandable on demand).
- Pipeline data: the modal also surfaces the deal's pipeline stage and
  value, sourced from Story 2.1 / 2.6's data, alongside attribution.

## Acceptance Criteria

1. Each appointment row on `/today` has a control to open a call-prep
   modal for that appointment's contact.
2. Opening the modal fetches and displays, for the appointment's
   `contactId`: attribution data, current pipeline stage, and deal value
   (from 2.1/2.6), and note history for that contact.
3. The contact's most recent note is shown expanded in full; any earlier
   notes are collapsed under a "show more" affordance and are not fetched
   or rendered expanded by default.
4. No contact, attribution, note, or pipeline data is fetched for a row
   until its modal is opened — `/today`'s initial load and row rendering
   make no additional per-row requests.
5. Closing the modal returns to `/today` with no change to the day view's
   state or scroll position.
6. If the contact has no notes, the modal shows an empty state instead of
   an error.
7. If the contact has no pipeline stage/value on record (e.g. not yet
   entered the pipeline), the modal shows that section as empty/not
   applicable rather than erroring.

## Dev note, 2026-08-20 — timezone fix in this story's files

`lib/ghl/appointments.ts` and `lib/ghl/format.ts` changed, but the story's
scope did not. Both formatted dates with no timezone, so they used the
process's own: the developer's zone locally and UTC in Cloud Run. A 9:00 AM
Central appointment rendered as "2:00 PM" on the call-prep panel this story
built, and `dayRange` moved "today" to tomorrow at about 6pm Central.

Both now take a timezone, defaulting to `DEFAULT_TIME_ZONE` in
`lib/time/zone.ts` (America/Chicago). `dayRange` no longer uses `setHours`,
which mutates in the process zone.

Status stays Ready. This is a production defect in already-shipped behaviour,
not new scope, and none of this story's own acceptance criteria changed.
