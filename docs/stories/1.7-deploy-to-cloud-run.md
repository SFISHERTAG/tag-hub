# Story 1.7 — Deploy to Cloud Run

**Epic:** 1 — Foundation and access
**Status:** Ready

## Story

As TAG, I want the Hub running on a real URL, so that other people can use it
and the OAuth install can point somewhere permanent.

## Context

The Hub only runs on `localhost:3000`. That blocks anyone else using it, and it
keeps the GHL redirect URI pointed at a machine that is usually asleep.

Cloud Run, Artifact Registry, and Cloud Build are enabled on `tag-success-hub`.
Secret Manager holds `ghl-pit`; the OAuth client secret needs adding.

## Acceptance criteria

1. A Dockerfile builds the app with Next.js standalone output.
2. Cloud Build builds on push to `main` and deploys to Cloud Run.
3. Secrets come from Secret Manager at runtime, never from a committed file or
   a plaintext environment variable.
4. The service runs as a dedicated service account with least privilege:
   Firestore user, Secret Manager accessor. Not the default compute account.
5. The production redirect URI is registered on the marketplace app and does
   **not** contain the string `ghl`.
6. Cold start to first byte is acceptable — minimum instances 0 is fine at this
   scale; revisit if it becomes unpleasant.

## Tasks

## Dev notes

Do not deploy before Story 1.3. A public URL with no authentication serves a
live CRM to anyone who finds it. These two stories are both "Ready", and the
order between them is not negotiable.

`GHL_PIT` should not exist in production. It is a single-location development
fallback; production resolves tokens through the agency install. Leaving it set
would mean a production bug could silently fall back to one tenant's credential.

The redirect URI rule bit us once already — the marketplace validator rejects
any URI containing `ghl`, which is why the routes are `/api/oauth/*`. The
production URI must clear the same rule.
