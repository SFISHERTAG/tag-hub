# Story 6.1 — Per-tenant duplicate-conversion audit

**Epic:** 6 — Acquisition loop
**Status:** Blocked — requires manual audit before implementation

## Story

As TAG, I want to verify that GHL is not already sending conversions to Meta, so that the Hub's dispatch (Stories 6.2–6.3) doesn't double-count and poison the algorithm.

## Context

**CRITICAL:** If GHL is already sending conversions to a client's Meta pixel, and the Hub also sends them, Meta receives duplicates and the algorithm optimizes against inflated outcomes — worse than no data.

This story is a manual audit, not code: for each client/pixel, check Meta Events Manager to see if GHL's Zapier/webhook is already firing conversions.

Once audit is complete:
- If pixel is clean → safe to enable Hub dispatch for that tenant
- If pixel is already sending → disable GHL integration or delay Hub dispatch until GHL is killed

## Acceptance criteria

1. **Audit checklist:** for each of 23 clients:
   - Log into their Meta Business Manager
   - Open Events Manager for their conversion pixel
   - Check "Test Events" tab for recent conversions (last 7 days)
   - Check event source: is it GHL, Zapier, or unknown?
   - Document findings in spreadsheet
2. **Per-client decision:** green (safe) / yellow (verify GHL will be disabled) / red (block for now)
3. **Only after audit:** enable Stories 6.2–6.3 for that tenant

## Blockers

- Manual task, requires Meta access for each client
- Findings must be documented before Hub dispatch goes live
- If most clients are green: implement and deploy 6.2–6.5
- If many are red: coordinate with GHL team to disable their integration first
