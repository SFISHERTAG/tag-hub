# Story 8.6 — A subtle bug affordance, always reachable

**Epic:** 8 — Operational instrumentation
**Status:** Draft — parked 2026-08-25, not started

## Story

As anyone using the Hub, when I hit something broken I want to report it from
where I am, without navigating away and without a button that competes for
attention the rest of the time.

## Context

**The feature already exists; the way in does not.** `/bug-reports` is built and
routed (`web/src/app/app.routes.ts:92`, feature module at
`web/src/app/features/bug-reports/` with a page, a form, a service and a model).
It shipped as part of story 10.4 and is Firestore-backed. What it has no route
into is the rest of the app: it is not in `nav-items.ts`, so unless you know the
URL, it is unreachable. That is the actual gap, and it is why bug reporting
exists but is not used.

**Epic 8's own table still calls 8.4 "In-app bug reporting — Draft"** while the
surface shipped under 10.4 (`docs/epics.md:229` against `docs/epics.md:536`).
That understatement is not corrected here; it belongs to whoever reconciles
Epic 8, and this story does not depend on it.

**Sam's reference is Claude Code's own bug glyph:** a small insect mark sitting
low and quiet in an otherwise empty surface, dark grey, no chrome, no label, no
container. It reads as ambient rather than offered. That is the target.

**This is the standing UI preference, not a new one.** Strip visible chrome;
hide affordances rather than deleting them. The same reasoning already decided
the drag handles in stories 10.10 and 10.11, where an existing non-interactive
element became the handle rather than adding a visible grip.

## Decisions

1. **Not a nav item.** Adding it to `NAV_ITEMS` puts a bug icon in the side rail
   and the bottom nav permanently, next to Dashboard and Clients. That is the
   opposite of the reference: bug reporting is not a destination you browse to,
   it is something you reach for at the moment something breaks.
2. **It lives in the shell, not in a feature.** `web/src/app/layout/shell/` is
   the only component every signed-in route renders inside
   (`shell.html:39-41`), so that is the one place an always-available affordance
   can live without every feature re-implementing it. The shell must not import
   from `features/bug-reports/`; it navigates by route, which keeps the
   architecture-isolation rule intact.
3. **Bottom-anchored, and the mobile case is the hard one.** Below 840px the
   shell renders `<nav class="bottom-nav">` (`shell.html:44-52`), so a
   bottom-anchored control collides with it. Options are to sit above the bottom
   nav, or to show the affordance only at `>=840px` the way story 10.12's resize
   handle does. **Not decided.** Pick during implementation with the phone in
   hand, and record which and why.
4. **Opacity, not absence.** Low resting opacity, full on hover and on
   `:focus-visible`. It must remain keyboard-reachable and must carry a real
   `aria-label`, because "subtle" is a visual decision and an invisible control
   is a broken one for anyone using a screen reader or tabbing.
5. **Route, do not modal.** First cut navigates to `/bug-reports`. A dialog that
   captures the current route as context is the better product, and is
   deliberately out of scope: this story is about being reachable at all.

## Acceptance criteria

1. A bug affordance renders in the shell on every signed-in route, without any
   feature module importing another.
2. It is visually quiet at rest and clearly resolves on hover and keyboard
   focus.
3. It is reachable by keyboard and carries an `aria-label` naming what it does.
4. Activating it reaches the existing `/bug-reports` surface. No change to the
   bug-report form, service, or model.
5. It does not overlap or obscure the bottom nav below 840px, by whichever
   route Decision 3 settles on, and that choice is written into the story.
6. `NAV_ITEMS` is unchanged: no new side-rail or bottom-nav entry.
7. M3 tokens only. No raw hex, no `!important`, no deep selectors.
8. The full Angular gate is green: `ng build --configuration production`,
   `ng lint`, `ng test --watch=false`.
