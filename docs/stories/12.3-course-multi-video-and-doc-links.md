# Story 12.3 — Course multi-video and doc links

**Epic:** 12 — Knowledge Base
**Status:** Review

## Story

As a CSM or sales rep working through a course, I want every video and reference document on a lesson to be reachable in the Hub, so that lessons with call recordings or linked docs are usable instead of silently dropping most of their content.

## Context

`course_subsections.loom_id` is a single nullable varchar, and the Angular course player renders it as one Loom iframe (`web/src/app/features/courses/course-player/course-player.ts`, `LOOM_EMBED_BASE`). That is the entire video story today.

The legacy Skool content does not fit it. A live re-crawl of the three `thedealclosers` classrooms (2026-08-21) found lessons carrying Fathom recordings, Google Drive recordings, and multiple videos on one lesson — "Call Recording Links" has 35 videos on a single page (24 Fathom, 11 Drive), and "Call Recordings of First Call" has 7 Fathom links and no Loom at all. Six lessons also carry Google Doc or Sheet reference links that have no home in the schema either.

This story lands the schema and the UI. Content import is story 12.4 and depends on this.

## Acceptance criteria

1. Two new Postgres tables in a new `functions/sql/` migration, mirroring how `course_checkboxes` is a child of `course_subsections` in `007_courses.sql`:
   - `course_subsection_videos` (id, subsection_id FK ON DELETE CASCADE, provider CHECK IN ('loom','fathom','drive'), external_id, label nullable, display_order, created_at)
   - `course_subsection_docs` (id, subsection_id FK ON DELETE CASCADE, label, url, display_order, created_at)
   Both with an index on (subsection_id, display_order) and `GRANT SELECT, INSERT, UPDATE, DELETE ... TO tag_app_user`.
2. `docs/data-model.md` documents both tables and why each exists, in the same commit.
3. `course_subsections.loom_id` is retained unchanged for backward compatibility. Existing seeded rows keep rendering with no data migration.
4. `lib/course/db.ts` `getSubsections` returns `videos[]` and `docs[]` per subsection, ordered by `display_order`. A subsection with a `loom_id` and no `course_subsection_videos` rows still renders its Loom.
5. Embed URL mapping lives in one place: Loom `https://www.loom.com/embed/{id}`, Fathom `https://fathom.video/embed/{id}`, Drive `https://drive.google.com/file/d/{id}/preview`. One live render of a Fathom and a Drive embed is confirmed before the story closes — the Loom form is already proven in production.
6. The Angular course player renders N videos per lesson as a lazy list: title/label rows, iframe created on click, never more than the opened ones in the DOM. A lesson with one video still shows that video without an extra click.
7. Doc links render as an anchor list, not an iframe.
8. `web/src/app/features/admin/courses/course-editor/subsection-editor` gains a repeatable video-row editor (provider select, URL or id input, optional label, reorder) and a repeatable doc-row editor. Pasting a full share URL is accepted and the id parsed out of it.
9. All API access goes through the typed service layer. No raw `HttpClient` in components. `OnPush`, signals, new control flow, no `any`, no non-null assertions.
10. No raw hex in any component `.scss`. No `!important`, no `::ng-deep`.
11. Gate passes: `ng build --configuration production && ng lint && ng test --watch=false` in `web/`, and `npm run check:functions` since the story touches `functions/sql`.

## Dev notes

**Two tables, not one with a `kind` column.** Videos need a `provider` CHECK and an `external_id`; docs need a free URL and always a label. Splitting them keeps both constraints honest and avoids a nullable-column matrix. Sam's call, 2026-08-21.

**Angular only.** The Next surfaces this feature used to live on (`app/courses/[courseId]/client.tsx`, `app/admin/courses/[courseId]/course-editor.tsx`) are retired under `legacy/`. Do not port anything there.

**Why lazy.** 35 unconditional iframes on the "Call Recording Links" lesson is unusable on a phone. Lazy list, load on click, confirmed by Sam 2026-08-21.

## Dev Agent Record

### Fathom does not embed, and that changes what 12.4 imports

AC5 asked for one live render per provider before bulk import. Checked on 2026-08-21 by serving a page with three real iframes and loading it in a browser:

- **Loom** `https://www.loom.com/embed/{id}` — renders. Control case, already in production.
- **Drive** `https://drive.google.com/file/d/{id}/preview` — renders, real player, confirmed with one of the actual imported recordings.
- **Fathom** `https://fathom.video/embed/{id}` — **blank**. It answers `HTTP 200` and its CSP deliberately omits `frame-ancestors`, so it is meant to be framed, but it paints nothing, framed or top-level. Its `/share/` page sets both `x-frame-options: SAMEORIGIN` and `frame-ancestors 'none'`, so that is not a substitute.

The embed formula came from the handoff marked "documented public embed convention, confirm before bulk import". It does not hold for the share ids this training uses.

Rather than ship a URL that renders an empty box, `video-embed.ts` carries an `EMBEDDABLE` map and Fathom is `false`: those rows render as a link out to the share page, opening in a new tab. Everything else about them is unchanged — same list, same ordering, same labels. Flip the flag to `true` when someone establishes the real Fathom embed form and the player starts framing them with no other change.

**This matters for 12.4.** 31 of the videos in the legacy import are Fathom: all 7 on "Call Recordings of First Call" and 24 of the 35 on "Call Recording Links". Under this build those lessons are lists of links, not players. That is a product decision worth making explicitly rather than discovering after the import.

### Other decisions

**Query count.** `getSubsections` previously issued one checkbox query per lesson. Adding videos and docs the same way would have made it three per lesson on a screen the audit already flagged for query waterfalls, so all three child fetches are now batched with `= ANY($1)`: four queries per section regardless of lesson count, asserted by a test.

**Reorder is whole-list and transactional.** A partial reorder that fails halfway leaves two rows sharing a `display_order`, and the read path's `ORDER BY` then returns them in planner order — a silent, unstable shuffle rather than a visible error.

**Link parsing is server-side.** The endpoint accepts a pasted share URL or a bare id and answers 400 on anything else, so the admin editor and the 12.4 import cannot disagree about what a valid id is. The old single-Loom field asked for "the id, not the whole URL" and stored whatever it was given.

**`loom_id` is untouched and unbackfilled.** Every already-seeded lesson still renders from it, and a test asserts the fallback specifically, because if it broke, every existing course would lose its video while the page still rendered perfectly well.
