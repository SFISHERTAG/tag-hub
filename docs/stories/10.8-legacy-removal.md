# Story 10.8 — Legacy removal

**Epic:** 10 — Angular migration
**Status:** Draft
**Depends on:** 10.7 (every remaining feature ported)

## Story

As the team maintaining this codebase, I want `legacy/` deleted and the four
exemptions that carry it removed in the same commit, so that the migration ends
with one implementation of every screen rather than a directory nobody is
allowed to touch and nobody is required to remove.

## Context

The big-bang cutover (`c5d1b75`) moved everything under `app/` except
`app/api/**` into `legacy/`: 30 top-level entries, 142 files. It was kept rather
than deleted because it is the reference implementation 10.5 through 10.7 port
from, 41 server actions and 32 screens of behaviour Angular has to reproduce.

**This story exists because the sweep was unowned.** Story 10.7 carried the
words "and legacy removal" in its title and nothing about it in its body: no
acceptance criterion, no task. `docs/ANGULAR_MIGRATION_PLAN.md` had already
predicted the shape of that failure when it rejected the retire-then-delete
pattern, warning about "a directory that has to be swept, three build exclusions,
and a two-step rule where one step does the job." All three exclusions exist. The
sweep did not. A deletion nobody owns is a deletion that does not happen, and the
cost of not happening compounds: every future grep, every rename, every
dependency bump has to reason about code that is not built, not linted, not
tested, and not live.

Its own story rather than a clause inside 10.7 because it grew. When the pattern
was rejected it meant a handful of replaced pages. It now spans the whole
pre-Angular application, and it has a hard prerequisite that 10.7's other work
does not: nothing may be deleted until its Angular replacement exists.

## Acceptance criteria

1. `legacy/` does not exist.
2. The three build exclusions that carried it are gone, and the tools see no
   change in scope because there is nothing left to exclude:
   - `tsconfig.json` `exclude` no longer lists `legacy`
   - `eslint.config.mjs` `ignores` no longer lists `legacy/**`
   - `vitest.config.mts` `exclude` no longer lists `legacy/**`
3. The role-string exemption in `scripts/check-story-status.mjs` is removed, so
   the check once again refuses every inline role string in the tree with no
   path carved out.
4. Nothing imports from `legacy/`: `grep -rn "legacy/" --include='*.ts'
   --include='*.tsx' --include='*.mjs' --include='*.json' .` returns only
   deletions of the lines this story removes.
5. Every screen `legacy/` held has an Angular equivalent reachable behind the
   shell. The inventory is enumerated in this story before deletion, not
   assumed, and each entry names the route that replaced it.
6. The full gate passes after deletion, both sides, with no exclusion doing the
   work: `npm test && npm run lint && npx tsc --noEmit`, `npm run
   check:functions`, `npm run web:gate`.

## Dev notes

**Deletion is the deliverable, not the cleanup after it.** This is 10.7's own
phrasing about Next screens, and it applies with more force here, because
`legacy/` is invisible to every gate. A Next screen left alive at least fails a
lint rule or shows up in a build. Nothing in the toolchain will ever tell you
`legacy/` is still there.

**Acceptance criterion 5 is the one with teeth.** Deleting the directory is a
single command. Knowing that all 32 screens were actually reproduced is the
work, and it cannot be inferred from the Angular side, because a screen nobody
ported leaves no trace over there. Enumerate from `legacy/` outward, not from
`web/src/app/features/` inward.

**Removing the exemptions is not optional and does not wait for a later story.**
An exemption whose subject is gone is worse than a live one: it reads as a rule
with a hole in it, and the next person to need a hole widens this one rather
than arguing for their own. Criterion 3 matters most of the four. It was added
because the cutover moved 32 screens' worth of inline role strings and the
pre-commit check blocked the commit over strings that were only relocated. That
justification dies with the directory.

**This story cannot start early.** Every criterion depends on 10.7 being
complete. Starting it before then means deleting the reference implementation
that the remaining feature stories are being written from.
