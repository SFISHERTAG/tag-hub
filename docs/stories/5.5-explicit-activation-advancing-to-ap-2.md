# Story 5.5 — Explicit activation, advancing to `AP 2 - Ads Launched`

**Epic:** 5 — Onboarding and campaign launch
**Status:** Done

## Story

As a CSM, I want to click "launch" and have the campaign go live + the client advance to the next stage in one atomic action, so that launch is auditable and onboarding progress is explicit.

## Context

Story 5.4 creates the campaign paused. This story activates it:
1. CSM clicks "Launch" on the preview (5.3).
2. Hub calls Meta API to unpause the campaign.
3. Hub updates the Fulfillment opportunity to stage `AP 2 - Ads Launched`.
4. Audit log records the CSM + timestamp (Story 3.5).
5. Redirect to onboarding checklist (5.1) showing updated stage.

All or nothing: if the Meta API call fails, the Fulfillment stage does not advance.

## Acceptance criteria

1. Function: `activateCampaign(locationId, campaignId, opportunityId)`.
2. Calls Meta API to unpause the campaign.
3. Updates Fulfillment opportunity to `AP 2 - Ads Launched`.
4. Saves audit log entry (CSM ID, timestamp, campaign ID, opportunity ID).
5. Returns updated Fulfillment stage.
6. On error: rollback both writes, throw with clear message.

## Dev notes

Depends on Story 4.1 (Meta API) and Story 5.4 (paused campaign creation).

### Transaction

AC6 as originally written ("on error: rollback both writes") doesn't fit this operation: Meta and GHL don't share a transaction, and "rolling back" a successful Meta unpause means issuing a second, independently-fallible network call — which can itself fail and leave the CSM in a third, worse-understood state instead of one of the two the story cares about. So the implementation is intentionally not symmetric:

- Meta call fails: nothing has changed. The thrown error is Meta's own (via `MetaApiError`/`MetaNotConfiguredError`), no GHL call is attempted, no audit entry is written.
- Meta succeeds, the AP2 stage can't be resolved, or the GHL stage update fails: the campaign **is live**. The thrown error says so explicitly ("Campaign {id} is now LIVE on Meta...") and tells the CSM to retry the stage move rather than re-launch the campaign. No audit entry is written for this path — the audit log records completed activations, not partial ones.
- Both succeed: one audit log entry records the CSM, timestamp, campaign ID, and opportunity ID.

This satisfies AC6's intent — the error message never leaves the CSM guessing which side succeeded — without pretending a cross-system rollback is safe to attempt.
