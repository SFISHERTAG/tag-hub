# Story 17.1 — Orchestration layer design

**Epic:** 17 — End-to-End Campaign Orchestration
**Status:** Blocked — waiting for Epic 10.4 (Angular migration calibration) to land

## Story

As the tech lead building the end-to-end orchestration, I need to design the full flow (actor video → editor → GHL → Meta → scheduling → KPI monitoring) before implementation starts, so that stories are built to a single locked design rather than discovered piece by piece.

## Context

Phases 1-3 (provisioning, intake+Gemini copy, Meta setup) are live. Epic 17 extends from "Meta account ready" to "campaign live, monitored, and scaling."

Seven design decisions block implementation:

1. **Actor/AI video generation** — Where does it live (Google Drive)? Who triggers it? 11labs API? Client-recorded fallback?
2. **Editor integration** — How does editor get video, process it, return it? Slack drop? Drive webhook? Manual step?
3. **GHL placeholder wiring** — How does Gemini inject video links into PSL/pre-call funnels? GHL API or manual update?
4. **Meta campaign creation** — Template structure? How many variations? Predetermined settings (budget, audiences, placements)?
5. **Scheduling (Mon-Thu-Sun)** — Cloud Scheduler vs. Pub/Sub vs. Firestore triggers? Thursday copy operation (duplicate to follow-up campaign)?
6. **KPI monitoring** — Which metrics? ROAS, cost-per-lead, show rate? Alert thresholds? Who gets notified?
7. **Budget scaling** — Based on what signal (ROAS, daily spend trend)? Automatic increase/decrease? Max ceiling?

## Acceptance criteria

1. Design document covers all seven decisions with rationale
2. Architecture diagram showing the full data flow (intake → actor → editor → GHL → Meta → scheduler → monitor → escalate)
3. Error handling and fallback paths (e.g., editor delays, video generation timeout, Meta API rate limit)
4. Integration points with existing systems are specified (Phase 2 Google Doc folder, Phase 3 Meta setup, Gemini service)
5. Stories 17.2–17.7 are sized and sequenced based on this design

## Tasks

- [ ] **Interview session:** Tech lead walks through each of the seven decisions with architect/builder
- [ ] **Design doc:** Lock the flow, diagram, error cases, and integration boundaries
- [ ] **Story breakdown:** Size 17.2–17.7 based on design
- [ ] **Approval:** Tech lead validates design before implementation starts

## Notes

This story is deliberately blocked on 10.4 landing. The portfolio migration calibration should inform whether there are shared patterns, primitives, or infrastructure that Epic 17 should reuse or depend on.

**Interview questions will cover:**
- Where does each artifact (video, edited video, copy variations) live and how does it move?
- What triggers the next step in the flow?
- Who makes decisions (automatic vs. human-in-the-loop)?
- What happens when a step fails or is delayed?
- Is this a pure Gemini orchestration (function calling), or does it hand off to Gspace, webhooks, or other systems?
