# Story 1.6 — Tenant registry and entitlements

**Epic:** 1 — Foundation and access
**Status:** In Progress
**Depends on:** 1.4 (✓ Done)

## Story

As TAG, I want each client's purchased services recorded against their tenant,
so that the Hub shows only what that client actually bought.

## Context

Services are à la carte. The entry offer is a VSL funnel plus ad management;
the closing team, website, and sales enablement are bought separately. A client
on ads only has no closers, so a pipeline board is meaningless to them.

The Fulfillment pipeline already encodes this ladder — `AP 4 - Closer Recruit`
sits between first deal and `AP 5 - Ascension`, because the closing team is the
upsell once ads are proving out.

## Acceptance criteria

1. Firestore holds a tenant document per location:
   ```
   locations/{locationId} → {
     name,
     services: { vslFunnel, adManagement, closingTeam, website, salesEnablement },
     metaAdAccountId, metaBusinessId, metaPixelId,
     ownerModel: 'client' | 'tag',
   }
   ```
2. Navigation renders only routes the tenant is entitled to.
3. An entitlement is enforced server-side as well as hidden in nav. Typing the
   URL for an unentitled route returns 404.
4. A tenant with no document defaults to no services — fail closed.
5. An admin screen lists tenants and toggles services.
6. Location names come from GHL rather than being typed twice.

## Dev notes

Fail closed on a missing document. A new sub-account appearing through the
agency install should show nothing until someone says what it bought — the
opposite default would expose features to a client who has not paid for them.

404 rather than 403 for an unentitled service. Unlike a wrong tenant, there is
nothing to conceal about existence here, and 404 reads correctly: for this
client, that page does not exist.

The three Meta ids live here because they are per-tenant configuration that
GHL has no concept of. They are unused until Epic 4 but belong in the shape now
rather than being bolted on.

## Post-implementation change: portfolio resilience (resweep High)

Status is unchanged.

`app/portfolio/page.tsx` fetched every tenant with `Promise.all(getTenant)`,
which rejects on the first failure, so one unreachable tenant record crashed
the client switcher for every other client. Changed to `Promise.allSettled`:
tenants that resolve render, and the number that did not is shown rather than
silently missing. `getTenant` itself is unchanged.
