# Story 1.2 — Agency OAuth install

**Epic:** 1 — Foundation and access
**Status:** Blocked — requires Agency Owner permission

## Story

As TAG, I want one agency-level install that reaches every sub-account, so that
adding a client does not mean provisioning another credential.

## Blocker

Marketplace app installation is an Agency Owner action. The current operator is
`AGENCY-ADMIN`; `AGENCY-OWNER` is Austyn Okafor. The same permission gates
sub-account creation, and the account picker showing one sub-account instead of
40 is likely the same cause.

## Acceptance criteria

1. The install completes and stores an agency token with `userType: Company`. ✓ built
2. A location-scoped install is accepted and stored separately. ✓ built
3. Location tokens are minted from the agency token on demand. ✓ built
4. All 40+ sub-accounts become reachable. ⨯ blocked
5. Sub-accounts are enumerated from GHL rather than configured by hand. ⨯ not built

## Implementation notes

Built: `app/api/oauth/install`, `app/api/oauth/callback`, `lib/ghl/oauth.ts`,
`lib/ghl/store.ts`.

Marketplace app configuration that this required, learned the hard way:
**Target User: Sub-Account** with **Agency & sub-account** install. Agency-only
targeting locks out all 144 sub-account scopes, which would leave the app able
to list sub-accounts and read nothing inside them. Target user cannot be
changed after app creation.

Redirect URIs may not contain the string `ghl`.
