# Story 5.4 — Create paused via Marketing API

**Epic:** 5 — Onboarding and campaign launch
**Status:** Done

## Story

As the Hub, I want to create a campaign in Meta Ads Manager via the Marketing API in paused state, so that CSM can review before it starts spending.

## Context

This is the machinery that makes the preview (5.3) real. Called by the "confirm" action on the preview, it:
1. Takes the preview data (template + form inputs).
2. Calls Meta Marketing API to create ad account, ad set, ads.
3. Sets all to paused.
4. Returns the created campaign ID + structure.

State is not yet advanced in GHL — that happens in Story 5.5 when CSM explicitly activates.

## Acceptance criteria

1. Function: `createPausedCampaign(locationId, templateId, formInputs)`.
2. Creates ad account (if needed), ad set, ads via Meta Marketing API.
3. All created resources are in paused state.
4. Returns: { campaignId, adSetId, adIds[], status: "paused" }.
5. On error: throw with clear message (e.g., "Invalid pixel ID").

- [x] Error handling for common failures (invalid pixel, auth, budget issues)

## Dev notes

Depends on Story 4.1 (Meta System User setup) — confirmed unblocked 2026-08-16.

Implemented in [lib/onboarding/campaign-launch.ts](../../lib/onboarding/campaign-launch.ts):
`createPausedCampaign(locationId, templateId, formInputs)` creates the campaign, ad
set, and one ad per template creative via the Meta Marketing API
(`lib/meta/client.ts`'s System User client), all left `PAUSED`. Every created resource
ID is logged to the Story 3.5 audit log (`lib/audit/store.ts`) under
`locations/{locationId}/auditLog`, action `campaign.create`.

**Ad account:** "creates ad account if needed" (AC2) is interpreted as *resolving* the
client's existing ad account (`Tenant.metaAdAccountId`, set in Story 4.1's client
onboarding), not programmatically creating a new funded Meta ad account — the Marketing
API doesn't support creating a billable ad account without a funding source and
Business Manager admin action, so that stays a manual onboarding step. If a tenant has
no `metaAdAccountId` configured, `createPausedCampaign` throws an actionable error
naming the missing config rather than attempting creation.

**Errors:** `toActionableError()` pattern-matches Meta's error text for pixel, auth, and
budget failures per AC5; anything else falls through to a labeled generic message
(never a bare "creation failed").

**Idempotency (5.6):** wired in as part of this story — `lib/onboarding/campaign-launch-store.ts`
tracks launch progress under `locations/{locationId}/campaignLaunches/{key}`, keyed by
a hash of (locationId, templateId, formInputs). A retry with identical inputs resumes
from the last completed resource (campaign created but ad set failed → only the ad set
and ads are retried) instead of re-creating everything, and a fully completed launch
returns the stored result without touching Meta again. Budget ceiling enforcement
(`lib/onboarding/offer-budgets.ts`) also lives here. Story 5.6's own doc should be
marked accordingly since its ACs are satisfied by this implementation, not a separate pass.
