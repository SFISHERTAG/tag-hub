# Story 7.9 — Admin: users, groups and role assignment

**Epic:** 7 — Command surface and configurability
**Status:** Backlog — shipped without a story, real state unverified

## Why this is a backlog item for shipped code

Six live endpoints exist under `app/api/admin/users/**` and **no epic mentions
this capability at all**. It was built, it is deployed, and nothing in the
planning system knows it exists.

Written under `AGENT_COORDINATION.md` §11: if it can run, it needs a story. The
Status is Backlog rather than Done deliberately — see Verification below. Nobody
has established that these endpoints still behave as intended, and inventing a
Done would be exactly the invented status §11 warns against.

## What is shipped

| Endpoint | Purpose |
| --- | --- |
| `admin/users` | List users |
| `admin/users/[uid]/role` | Assign a role to a user |
| `admin/users/groups` | List and create groups |
| `admin/users/groups/[groupId]` | Read, update, delete a group |
| `admin/users/groups/[groupId]/members` | List and add members |
| `admin/users/groups/[groupId]/members/[uid]` | Remove a member |

Backed by `lib/auth/groups.ts`, migrated onto the repository seam in story 14.1.

## Why it matters more than its size suggests

This is the write path for **role claims**. `admin/users/[uid]/role` calls
`setUserClaims`, and group membership changes re-apply a group's role to every
member. That means this surface can grant and revoke access across the whole
product, and it has never had a story stating what it is allowed to do.

It also intersects Epic 15 directly. 15.I is "Grant store, reconciler, templates,
admin", which will either absorb this or replace it. Whichever happens, it should
happen knowingly rather than by collision.

## Acceptance criteria

1. [ ] Establish the current behaviour of all six endpoints against code and record it here, rather than assuming from the route names
2. [ ] Every endpoint is confirmed to require an admin role via `PermissionService` / `ROLES.*`, with no inline role strings (story 14.B's scanner now enforces the second half)
3. [ ] Group role changes re-apply to existing members, and the story states what happens to a member removed from a group — `lib/auth/groups.ts` deliberately does **not** revoke claims on removal, and that decision needs to be stated somewhere a reader will find it
4. [ ] The claims byte cap is enforced on every write path here, per the verified 1000-byte limit
5. [ ] Reconciled with Epic 15.I: absorbed, superseded, or explicitly kept

## Verification

**None of the above is verified.** This story exists to make an untracked
surface visible, not to claim it works. The first task is establishing what is
true.
