# Story 11.8 — Triage the unmerged branches

**Epic:** 11 — Migration readiness
**Status:** Draft

## Story

As whoever maintains this repo, I need every branch carrying unmerged commits
resolved into landed, cherry-picked, or deleted, so that work nobody can find is
either recovered or admitted to be gone.

## The problem

**31 branches carry commits that are not on `main`.** Several contain real,
wanted work. Nothing tracks any of it, and the distances make a bulk merge
actively dangerous:

## Why a bulk merge is the wrong move

**The stale ones predate the guards.** Branches 251+ behind sit before
`check-branch-freshness` existed. That check refuses commits on branches this
stale precisely because their green results stop meaning anything — the gates
they ran are not the gates `main` has now. Merging them routes around the guard
written for this exact case.

**Branch names do not tell you what is superseded.** Two examples found while
writing this story, both in five minutes:

- `deploy-method-guard` sounds essential — it documents the deploy method that
  took production down for four and a half hours. **It is already superseded.**
  `main`'s `docs/DEPLOYING_THE_APP.md` is 187 lines and carries the `--source`
  warning; the branch's version is 131 lines. Merging it would move that
  document *backwards*.
- `phase1-security-fixes` contains "Sign TAG's own internal calls into the
  phase2/3 onboarding webhooks". That work **landed by another route**:
  `lib/api/webhook-auth.ts` is on `main` today and is what stories 5.12 and 5.13
  depend on.

So the branch list is not a to-do list. It is a set of claims, each needing a
content-level check.

**And some of it is genuinely wanted.** `resweep-critical-fixes` carries fifteen
commits with messages like "Fix four core-infra findings: migration, approval
race, false revert, null wipe" and "stop erasing course progress". `ci/github-actions`
claims to close "a contracts job that was passing vacuously" — a vacuous green
check is the failure mode `AGENT_COORDINATION.md` §10 order 2 exists for.

## Acceptance criteria

1. [ ] Every branch ahead of `main` is classified **superseded**, **wanted**, or
   **dead**, with the evidence recorded per branch — not the branch name, and
   not the commit subject
2. [ ] "Superseded" is proven by comparing *content* against `main`, the way
   `deploy-method-guard` and `phase1-security-fixes` were here
3. [ ] "Wanted" commits are cherry-picked onto a fresh branch cut from current
   `main`, gated, and landed individually — never by merging a stale branch
4. [ ] "Dead" branches are deleted, and the story records what was in them so the
   deletion is auditable
5. [ ] Anything security-related is read line by line before any verdict:
   `resweep-critical-fixes` and `phase1-security-fixes` between them touch
   auth, idempotency, tenant isolation and course progress
6. [ ] The story states which branches were deleted and by whom

## Dev notes

**Do not merge stale branches. Cherry-pick onto fresh.** A branch 237 behind
replays a five-day-old tree against one that has since gained the repository
seam, six mechanised guards, and the Angular sign-in. The conflicts would be
resolved by whoever is least equipped to judge them: whoever is doing the merge.

**Read the security branches first.** They are the ones where "already fixed
another way" and "still broken" look identical from outside, and where being
wrong is expensive in both directions — re-applying a landed fix is noise,
skipping an unlanded one is a live defect.

**Expect partial supersession.** `phase1-security-fixes` has nine commits and at
least one has landed elsewhere. Assume per-commit, not per-branch.

**`hold/main-parked` is already resolved** and is the cheapest possible example
of the pattern: it shows 1 ahead, and that commit is the Secretary's handoff,
which was recovered and landed on `main` at `d28a69d`. Ahead of `main` does not
mean it contains something `main` lacks.

**This is a day of careful work, not an afternoon.** It exists as a story rather
than a task because `AGENT_COORDINATION.md` §11 applies: 31 branches of
unreviewed work can rot silently, and nothing currently watches them.
