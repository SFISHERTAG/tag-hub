# Story 3.3 — Enter a client tenant

**Epic:** 3 — CSM portfolio and impersonation
**Status:** Done

## Story

As a CSM, I want to click "enter" on a client and be taken into their account to work in it, so that I can troubleshoot, close deals, or run onboarding without context switching.

## Context

Impersonation is a redirect model (not a modal or sidebar). When a CSM enters a client tenant, they authenticate as that client (locationId changes), see that client's board/today/followup, and see an unmistakable banner (Story 3.4) showing they are impersonating.

The entry itself is an audit event (Story 3.5) — who entered which location, when, and what they did there.

## Acceptance criteria

1. Portfolio card (3.1) has an "enter" button/link that initiates impersonation.
2. Clicking it creates an audit log entry (3.5), then redirects to `/?impersonate=true`.
3. The redirect sets a session/cookie flag that authentication checks on every request.
4. While impersonated, all GHL requests use the client's locationId, not the CSM's.
5. An exit button on the banner (3.4) clears the flag and redirects back to `/portfolio`.

## Dev notes (implementation)

Built together with 3.4 (banner) and 3.5 (audit log), per this story's own context — see those files for their own checklists. Note: this was implemented concurrently by two parallel sessions against the same repo; the pieces below are the converged result, not two competing versions. Key pieces:

- `lib/auth/session.ts`: `IMPERSONATION_COOKIE`, `getImpersonation()`, and an updated `requireLocationAccess()` that grants a `tag_csm` access to a location outside their static claim only when the impersonation cookie names that exact location and actor.
- `lib/auth/impersonation-actions.ts`: `enterImpersonation(locationId)` creates the Story 3.5 audit entry document, sets the cookie (carrying that doc's id as `auditEntryId`), then redirects; `exitImpersonation()` updates that same document with an exit timestamp, clears the cookie, redirects to `/portfolio`.
- `app/portfolio/page.tsx`: the "enter" affordance is a form posting to `enterImpersonation`, bound per client card.
- `app/impersonation-banner.tsx`, wired into `app/layout.tsx` (root layout, not just the location-scoped one): the banner (3.4), server-rendered since the cookie is httpOnly, shown on every page while impersonating and shifting the header down so it never overlaps.
