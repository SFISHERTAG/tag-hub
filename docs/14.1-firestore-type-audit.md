# Firestore Type Audit — Declared vs. Actual Field Coverage

**Date:** 2026-08-23  
**Baseline:** Master's branch `claude/story-14-1-repository-seam-e557d0` (commit 495aa43)  
**Method:** Examine writers (not readers) for all 23 document paths in lib/data/repository.ts. Extract union of fields written to Firestore. Compare to declared types. Report gaps (written but undeclared, or declared but never written).

**Scope:** functions/src, scripts/, lib/, app/. Does NOT include web/src (no Firebase there).

---

## Critical Findings Summary

### 1. `locations/{locationId}` — CRITICAL TYPE GAP

**Declared type (StoredLocation):**
```typescript
export type StoredLocation = Tenant & {
  readonly slackChannelId?: string;
  readonly driveFolderId?: string;
  readonly metaSetupStatus?: string;
  readonly metaAccessRequestedAt?: string;
  readonly metaSetupGuidesentAt?: string;
};
```

**Fields WRITTEN but NOT declared:**
- `locationId` (always written, functions/src/firestore.ts:96)
- `googleDocId` (written by saveTenantResources, conditionally)
- `ownerEmail` (written by saveTenantResources, conditionally)
- `metaAdAccountId` (written by saveTenantResources, conditionally)
- `metaBusinessId` (written by saveTenantResources, conditionally)
- `metaPixelId` (written by saveTenantResources, conditionally)
- `services` (object: vslFunnel, adManagement, closingTeam, website, salesEnablement — always written)
- `ownerModel` (always written, value: "client")
- `createdAt` (always written as new Date())
- `provisioned` (always written, value: true)

**Impact:** These fields exist in live Firestore documents but are invisible to the type system. When 14.4–14.9 migrate this collection to Postgres, these fields will be silently dropped unless the migration explicitly enumerates them.

**Root cause:** Type was written against what `lib/ghl/tenants.ts` (a reader) wanted rather than what `functions/src/firestore.ts#saveTenantResources` (the writer) puts there.

**Fix required:** Update StoredLocation type to include all actually-written fields before migration.

### 2. FieldValue Sentinels — VERIFIED (all three present)

| Sentinel | Site | Purpose | Postgres equivalent | Notes |
|----------|------|---------|-------------------|-------|
| `FieldValue.serverTimestamp()` | `lib/bug-reports.ts:41` | Auto-assigned creation timestamp | `now()` | Must be migrated to generated column or trigger |
| `FieldValue.delete()` | `lib/onboarding/store.ts:39` | Delete nested JSON field | `jsonb` DELETE operator | Nested (inside `completedTasks[taskId]`) |
| `FieldValue.arrayUnion()` | `functions/src/firestore.ts:35` | Append to array (email whitelist) | `array_append()` | Part of Phase 1 seeding (otpWhitelist) |

**Finding:** These three are live. The first pass of the 14.1 audit missed them. Critical for migration: Postgres equivalents must be implemented before data moves.

### 3. Exactly-Once Write Guarantees — TWO SITES

Both use `.create()` instead of `.set()` to fail if the document already exists, preventing double-processing on webhook retries or concurrent operations.

| Path | Site | Operation | Impact if lost |
|------|------|-----------|-----------------|
| `webhookEventsProcessed/{source}:{eventId}` | `lib/webhooks/idempotency.ts:34` | Mark webhook processed | Webhook double-processes (state applies twice) |
| `locations/{locationId}/campaignLaunches/{key}` | `lib/onboarding/campaign-launch-store.ts:68` | Create in-progress launch | Second caller overwrites incomplete work |

**Warning:** First pass of 14.1 audit found only one `.create()` site. Independent re-audit found both. Inventory validation is essential.

---

### 4. Server-Assigned Timestamps — INCONSISTENT

| Collection | Field | Timestamp type | Pattern |
|-------------|-------|-----------------|---------|
| `authCodes` | `issuedAt`, `expiresAt` | `Timestamp.now()` (Firestore SDK) | Normalised to epoch millis on read by lib/auth/otp.ts |
| `authCodeCooldowns` | `lastIssuedAt` | `Timestamp.now()` | Read as Timestamp, converted to millis |
| `bug_reports` | `createdAt` (implied) | `FieldValue.serverTimestamp()` | Server-assigned, actual value unknown to caller |
| `locations` | `createdAt` | `new Date()` | Client timestamp, JavaScript Date object |

**Gap:** Two patterns exist for "now" — Firestore's `Timestamp.now()` and server-side `FieldValue.serverTimestamp()`. Types don't distinguish, and migration code will silently use wrong one if not explicit.

## Methodology Notes

**Why examining WRITERS, not readers:** A reader's type describes what that reader wanted to do. Only writers say what's actually in the document. This audit examines all `.set()`, `.update()`, `.add()`, `.create()`, `batch.set()`, `batch.update()`, `tx.set()`, `tx.update()` calls.

**Validation method used:** Grep-searched for known field (`primaryCompanyId`) and confirmed the search found it before proceeding. `git grep -E` does not support `\s` in this environment; used plain `grep` instead.

**Completeness:** This audit covers all 23 paths declared in Master's 14.1 audit doc. PENDING status indicates paths where the field inventory is not yet extracted; MATCH/CRITICAL/EXACTLY-ONCE are verified findings.

## Acceptance Criteria for Stories 14.4–14.9

Before any migration story begins:
1. **Update types** to match actual writes (especially `StoredLocation`)
2. **Handle FieldValue sentinels** — no Postgres equivalent will be selected automatically
3. **Preserve exactly-once semantics** — `.create()` must become `ON CONFLICT ... DO NOTHING` or similar
4. **Verify all fields are migrated** — read this audit before writing the SELECT that populates the new table
